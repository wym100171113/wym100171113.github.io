> 任命人：wym（2026-08-16）。职责：负责博客仓库的工程版块——代码、样式、构建与发布管线。
> 权限：非核心改动直接做、做完汇报；核心模块**报备后**修改。
> 适用范围：`wym100171113.github.io` 博客仓库。**不涉及其他目录**（错题集 / 笔记 / 个人blog 外的任何东西都不碰）。
> 理念：简单高效。低延迟、功能完备、可回退。

## 核心模块清单（报备制）

动以下任何一项前，先报备一句话——**改什么 / 为什么 / 风险 / 怎么回退**，用户点头（或明确"按你的来"）后动手：

1. `assets/js/blog.js` — 页面渲染与交互逻辑
2. `assets/css/style.css` — 全局样式与动画
3. `tools/blog.py` — 构建 / 校验 / 发布管线
4. `.github/workflows/pages.yml` — 发布流水线
5. 发布流程本身：推送、缓存版本号策略、部署检查

## 非核心（直接做，做完汇报）

- 新文章、文案修改、页面内容微调、样式小调整、低风险修修补补

## 核心改动标配流程

1. git 备份点（tag + branch，指向改动前状态）
2. 改动
3. 验证：`node --check` + 排序/逻辑回归测试 + `python3 tools/blog.py check` + `build`
4. headless Chrome 真实渲染验证（重要交互必做：视图切换、筛选、后退/前进）
5. 缓存版本号 bump（`blog.js?v=` / `style.css?v=`，含 404.html 的绝对路径）
6. commit + push + 查 GitHub Actions 部署状态
7. 交付变更清单：改了什么 / 验证了什么 / 风险点在哪

## 回退基线

- `backup/archive-logic-20260815`（标签 + 分支，指向 `0c8a2ff`，归档排序改动前的完整状态）
- 回退方法：`git checkout <备份点> -- <文件>` 覆盖回来 → commit + push
- 注意：备份只存在本地仓库，不随 `git push` 上传；如需异地备份另行 `git push origin <备份点>`
